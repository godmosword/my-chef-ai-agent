# AI Coding Workflow Prompt（chef-ai-agent / 通用版）

本檔定義四個模式：EVAL、IMPLEMENT、IMPLEMENT-QUICK、ROLLBACK。
每次對話開頭，由我（user）明確指定當前模式。未指定 = 預設 EVAL。

═══════════════════════════════════════════════════════════
## 全域規則（所有模式都適用）
═══════════════════════════════════════════════════════════

### 模式切換
- 模式由我以 `MODE: <名稱>` 明確宣告，AI 不得自行切換
- 任一模式內，未獲明確指令前不得進入下一階段

### 永遠禁止（不論模式）
- 不得執行 `git commit`、`git push`、`git checkout` 切分支、`git reset`、`git revert`
- 不得修改 `package.json`、`tsconfig.json`、`tailwind.config.*`、`next.config.*`、
  `.env*`、CI / deploy 設定檔（除非該檔明確列入當次授權）
- 不得 `npm/pnpm/yarn install` 任何新依賴；若規格暗示需要，停下回報
- 不得 reformat 整個檔案；只改該改的行，保持 diff 乾淨
- 不得修改 `*.test.*` / `*.spec.*`（除非明確授權）
- 不得用 shell 繞過編輯限制（`sed -i`、`echo >`、`cat >`、`mv`、`cp` 覆寫等）
- 不得自行詮釋模糊規格；模糊處立即停下詢問

### 確認觸發詞（解除實作禁令的唯一方式）
- 僅以下用詞視為授權：「開始」「實作」「Apply」「下一個」「繼續」「Go」
- 「OK」「同意」「好」「看起來不錯」「這樣很棒」皆 **不** 視為實作授權
- 不確定時，主動詢問，不得自行判斷

### 中止觸發詞（立即停手）
- 「停」「stop」「halt」「pause」「等等」「先別動」

### Code snippet 規則（EVAL 模式下）
- 僅以 markdown code block 呈現
- 每段 ≤ 30 行
- 開頭標註「⚠ 參考用 snippet，請勿 apply」
- 不得提供完整檔案內容

## MODE: EVAL（READ-ONLY 評估模式）
═══════════════════════════════════════════════════════════

### 目的
檢視 UX/UI、架構、code quality，提出建議。不修改任何東西。

### 允許
- 唯讀指令：`ls`、`cat`、`grep`、`find`、`git status`、`git diff`、`git log`
- 提出問題、建議、優先級排序
- 提供參考 snippet（遵守上述規則）

### 嚴格禁止
- 任何形式的檔案修改、新增、刪除、rename
- 任何 file mutation tool 呼叫（edit_file、create_file、write_file 等）
- 任何寫入磁碟的 shell 指令
- 若以 Cursor Agent 模式運作，本任務請降級為 Ask / Chat 模式

### 輸出格式（每條建議）
1. **現況問題**
2. **建議修改方向**
3. **建議涉及的檔案**（含完整路徑）
4. **參考實作方式**（snippet）
5. **優先級**（P0/P1/P2）+ **風險** + **建議實作順序**

### 分批 review
- 建議數 > 5 項：先輸出「建議總覽」（每項一行），等我指定再展開
- 不要一次傾倒全部細節

### 結尾固定句
所有建議輸出完畢後，以這句結束：
> 「以上為唯讀分析，請指示要深入哪一項或實作哪一項。」

## MODE: IMPLEMENT（完整實作授權模式）
═══════════════════════════════════════════════════════════

### 用於
跨多檔、有風險、需要分批驗證的改動。

### 授權範圍宣告（我會在指令中填入）
- **授權實作項目編號**：[例：P0-1, P1-3]
- **授權修改檔案**：[完整路徑清單]
- 未列入者 = 未授權 = 禁止修改（即使「為了一致性」）

### 規格來源
- 以前一輪 EVAL 的對應「五段式規格」為唯一依據
- 規格與現有 code 衝突、或描述模糊 → 立即停下詢問，不得自行詮釋

### Pre-flight（開工前必做，依序執行並回報）
1. `git status` 確認 working tree
2. 若有未 commit 變更 → 警告我並停下
3. 建議我手動執行 `git checkout -b feat/[簡述]`（AI 不執行）
4. 列出本次將修改的檔案清單，再次確認對齊授權範圍
5. 等我回「開始」才動第一個檔案

### 實作中規則
- **一次一個檔案**，改完輸出 diff summary：
  ```
  檔案：path/to/file.tsx
  變更：+ N lines / - N lines
  說明：（3 句內）
  ```
- 改完一檔，等我回「下一個」或「繼續」才動下一檔
- 中途發現需動授權外的檔案 → 立即停下回報，**不得**自行擴大
- Type error / lint error → 先回報，**不**自動 fix（fix 可能擴大改動）

### 額外禁止（IMPLEMENT 模式專屬）
- 不得自行決定變數 / component / 檔案命名；以規格為準，模糊處問我
- 不得「順手優化」未列入授權的程式碼
- 不得引入新依賴（即使規格似乎需要 → 停下回報）

### 中止條件（觸發即停，等指示）
- 我輸入任一中止詞
- 規格需要新依賴
- 需修改授權外檔案
- 修改會破壞現有功能（route、type 衝突等）
- 連續兩次 lint / type error 修不掉
- working tree 出現非預期變更

### Post-flight Report（全部完成後輸出）
```
## 實作完成報告

### 已修改檔案
- `path/to/file1.tsx`: 一句話說明
- `path/to/file2.css`: 一句話說明

### 未動的檔案（授權內但判斷不需改）
- `path/to/file3.tsx`: 原因

### 偏離規格之處（如有）
- 規格 X 要求 A，實際做 B，原因：...
- （若無，寫「無」）

### 風險與後續
- 可能影響的其他頁面 / 功能
- 建議手動驗證路徑（點哪幾頁、跑哪個 flow）
- 建議的 commit message（給我參考，不要 commit）

### 下一步建議
- 具體指示（例：`pnpm dev` 並打開 /app）
```

### 開工確認（收到本模式指令後，先回覆）
1. 你理解的授權範圍（編號 + 檔案）
2. 計劃的實作順序（一檔一檔列）
3. 預期需要詢問的模糊點（如有）
4. Pre-flight 第 1-4 項執行結果
5. 等我回「開始」才動第一個檔案

## MODE: IMPLEMENT-QUICK（單檔快速授權模式）
═══════════════════════════════════════════════════════════

### 用於
單一檔案的小改動，跑完整 IMPLEMENT 太重。

### 授權範圍宣告
- **授權檔案**：[單一檔案路徑]
- **授權範圍**：[一句話描述要改什麼]

### 規則
- 只改這個檔案、只改這件事
- 不改其他檔案、不引入新依賴
- 跳過 Pre-flight 完整流程，但仍需先 `git status` 確認 working tree 乾淨
- 改完直接給 diff summary（格式同 IMPLEMENT 模式）
- 偏離原描述或需擴大範圍 → 立即停下問我
- 改完不需 Post-flight 完整報告，但需給：
  - diff summary
  - 一句話風險說明
  - 建議驗證方式

## MODE: ROLLBACK（回退 / 駁回模式）
═══════════════════════════════════════════════════════════

### 用於
剛實作完不滿意，需要回退或局部撤銷。

### 核心原則
**Rollback 不得變成新的失控變更。** AI 不得自行 git reset / git revert /
git checkout，所有 git 操作由我手動執行。

### 兩種 rollback 路徑

#### 路徑 A：完整丟棄（最安全，推薦）
若改動還沒 commit：
1. AI 回覆：「建議你執行 `git restore .` 丟棄全部未 commit 變更」
2. 列出將被丟棄的檔案清單（從 `git status` 取得）
3. 等我確認後手動執行；AI 不執行 git 指令

若已 commit 但還沒 push：
1. AI 回覆建議的 `git reset --soft HEAD~N` 指令（N 為要回退的 commit 數）
2. 解釋 soft / mixed / hard 的差異讓我選
3. 我手動執行

#### 路徑 B：局部撤銷（精準回退指定變更）
1. 我明確指定：要撤銷哪個檔案的哪個改動
2. AI 先輸出「撤銷計畫」：
   - 將恢復為哪個狀態（前次 commit / 我描述的版本）
   - 影響範圍
   - 連帶可能需要同步調整的地方（列出但不修改）
3. 等我回「執行撤銷」
4. AI 以「修改檔案」方式恢復內容（視為一次新的 IMPLEMENT-QUICK）
5. 遵守 IMPLEMENT-QUICK 的所有規則（diff summary、不擴大範圍等）

### 嚴格禁止（ROLLBACK 模式專屬）
- 不得執行任何 git 指令（包括看似安全的 `git restore`、`git checkout --`）
- 不得「順便修正」其他看到的問題
- 不得在撤銷時引入新邏輯，即使「比原本好」
- 撤銷範圍若不明確，停下問我，不得自行判斷

### Rollback 後必做
1. 提醒我手動 `pnpm dev` 驗證
2. 列出需要重新測試的功能點
3. 若是路徑 B（局部撤銷），輸出 diff summary

## 使用範例
═══════════════════════════════════════════════════════════

### 評估
```
MODE: EVAL
請檢視 /app 首頁的 UX/UI
```

### 完整實作
```
MODE: IMPLEMENT
授權實作項目編號：P0-1, P0-2
授權修改檔案：
- app/(main)/app/page.tsx
- components/InputHero.tsx
- components/QuickChips.tsx
```

### 單檔快速實作
```
MODE: IMPLEMENT-QUICK
授權檔案：components/RecipeCard.tsx
授權範圍：把圓角從 rounded-lg 改成 rounded-xl，並加上 hover:shadow-md
```

### 回退
```
MODE: ROLLBACK
剛剛 InputHero.tsx 的 placeholder 輪播改壞了，
請給我路徑 A（完整丟棄未 commit 變更）的執行計畫
```
